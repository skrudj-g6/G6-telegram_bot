# Бэкап и восстановление

Копируется PostgreSQL (игроки, заявки, история, сотрудники, аудит, настройки). Файлы чеков не копируются: они живут 7 дней и не критичны.

## Бэкап
```bash
./scripts/backup.sh
```
Скрипт делает `pg_dump -Fc`, проверяет, что архив читается, кладёт в `backups/altyn-ГГГГММДД-ЧЧММСС.dump`, удаляет копии старше `BACKUP_KEEP_DAYS` (по умолчанию 14) и, если задан `BACKUP_REMOTE` (rsync/ssh), копирует файл на другой сервер. Оборванный дамп не сохраняется.

Ежедневно в 04:00 (`crontab -e`):
```
0 4 * * * cd /opt/altyn && ./scripts/backup.sh >> backups/backup.log 2>&1
```

**Только копия на том же диске не защищает от потери сервера.** Настройте `BACKUP_REMOTE` на другой сервер или забирайте `backups/` к себе.

## Восстановление
```bash
./scripts/restore.sh backups/altyn-20261110-040000.dump
```
Скрипт проверяет файл, просит ввести `yes`, останавливает backend/бот/панель, пересоздаёт базу, загружает дамп и запускает сервисы (недостающие миграции применяются при старте backend).

## Проверка бэкапов
Раз в месяц восстановите последний дамп на тестовой машине (`docker compose up -d db`, затем `restore.sh`) и откройте панель. Бэкап, который ни разу не восстанавливали, считать рабочим нельзя.
